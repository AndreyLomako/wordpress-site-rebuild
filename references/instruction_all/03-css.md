# CSS темы

## Файлы и порядок

- `assets/css/main.css` — переменные, сброс, шрифты, общие стили, компоненты, страницы и формы.
- `assets/css/media.css` — медиазапросы; подключается после `main.css` средствами WordPress.
- CSS библиотек и плагинов остаётся в их файлах. Ограничение на два файла относится к собственным основным стилям темы, а не к ресурсам ядра и плагинов.

Секции `main.css` разделяем комментариями в порядке: ПЕРЕМЕННЫЕ → СБРОС → ШРИФТЫ → ГЛОБАЛЬНЫЕ СТИЛИ → HOVER → НАВИГАЦИЯ СЛАЙДЕРОВ → ШАПКА → ПОДВАЛ → МОБИЛЬНАЯ НАВИГАЦИЯ → БЛОКИ СТРАНИЦ → ФОРМЫ. Отсутствующие компоненты не требуют пустой секции.

## База

```css
*, *::before, *::after { box-sizing: border-box; }
body { margin: 0; }
img, video { max-width: 100%; height: auto; }
input, button, textarea, select { font: inherit; }
```

Сброс дополняем под проект и проверяем на контенте редактора и формах плагинов. Не удаляем фокус, маркеры содержательных списков и отступы статей без замены нужным оформлением.

- Общие цвета, типографику и размеры контейнера выносим в CSS-переменные. Не создаём переменную под каждое разовое значение.
- `.container` ограничивает ширину и задаёт горизонтальные отступы; `.wrapper` объединяет каркас сайта. Фон, ширины и шрифты определяются дизайном, а не значениями из примера.
- Модификаторы пишем составным селектором своего компонента. Не используем глобальный класс состояния для несвязанных блоков.
- Учитываем штатную разметку Contact Form 7, текста редактора и изображений WordPress.

## Адаптив

Для нового проекта исходный набор контрольных ширин: ширина контейнера, 1439.98, 1023.98, 767.98 и 479.98 px. Это соглашение, а не запрет нужных дополнительных точек. Проверяем также промежуточные ширины, отсутствие горизонтального скролла и переполнения длинным текстом.

При переносе сначала восстанавливаем фактические брейкпоинты и поведение оригинала. Не заменяем их стандартным набором, если меняется компоновка. Все собственные медиазапросы собираем в `media.css`, сохраняя порядок каскада.

## Состояния и позиционирование

- Для интерактивных состояний используем переходы конкретных свойств. Скорость определяется дизайном; для нового проекта допустима база `0.3s ease`.
- Учитываем `prefers-reduced-motion`; отключение движения в этом режиме допустимо.
- Для sticky-блоков проверяем прокручиваемого родителя, `overflow` и верхний отступ. `overflow: clip` используем только там, где соответствует нужному поведению.
- Декоративные эффекты не должны мешать кликам, фокусу и чтению. Новые эффекты не добавляем в переносимый сайт без задания.
