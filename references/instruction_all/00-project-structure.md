# Структура классической темы WordPress

```text
theme-slug/
├── style.css
├── functions.php
├── index.php
├── header.php
├── footer.php
├── front-page.php
├── page.php
├── single.php
├── archive.php
├── 404.php
├── screenshot.png
├── inc/
├── Parts/
│   ├── common/
│   └── home/
├── assets/
│   ├── css/main.css
│   ├── css/media.css
│   ├── js/main.js
│   ├── img/
│   ├── font/
│   └── lib/
└── acf-json/
```

Это схема размещения, а не перечень обязательных пустых файлов. Для распознавания классической темы нужны `style.css` с метаданными и `index.php`; остальные шаблоны создаём по реальным страницам и иерархии WordPress. Папки создаём при наличии содержимого. `acf-json` нужен при выборе Local JSON; вместо него допустима регистрация групп полей в PHP.

- Корень содержит шаблоны WordPress; главная страница учитывает настройку «Чтение» и назначение `front-page.php` и `home.php`.
- `functions.php` подключает общую PHP-логику. Разделяем её на небольшие файлы внутри `inc`, когда это упрощает поддержку; конкретный набор модулей не фиксирован.
- `Parts` содержит повторно используемые секции и карточки. Подключение — через `get_template_part()`, с передачей нужных данных аргументами. В существующей теме сохраняем её регистр папки и соглашения.
- Ресурсы оформления находятся в `assets`. Пользовательские фотографии и изображения контента загружаются в медиатеку WordPress, а не хранятся как обязательные файлы темы.
- `style.css` остаётся в корне для метаданных темы. Основные стили размещаем в `assets/css/main.css`, медиазапросы — в `assets/css/media.css`.
- Внутри `assets/lib` каждая используемая библиотека находится в собственной папке. Медиа, документы и другие нужные типы ресурсов имеют свои подходящие места; неизвестные файлы не удаляем автоматически.
- При переносе файлов обновляем PHP-подключения, зависимости, ссылки в CSS и JS. Не переносим файлы WordPress, плагинов и содержимое uploads в папки ресурсов темы.

Сайт открываем через локальный PHP-сервер с WordPress или тестовый стенд. Проверяем также постоянные ссылки и подключение базы; открытие PHP-файла напрямую в браузере не является проверкой темы.
