# PHP-шаблоны страниц WordPress

Сайт состоит из страниц WordPress и PHP-шаблонов темы, а не отдельных статических HTML-файлов. Шапка, подвал и общие секции не копируются в каждый файл.

## Каркас

`header.php` открывает документ и общий каркас:

```php
<!doctype html>
<html <?php language_attributes(); ?>>
<head>
  <meta charset="<?php bloginfo( 'charset' ); ?>">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <?php wp_head(); ?>
</head>
<body <?php body_class(); ?>>
<?php wp_body_open(); ?>
<div class="wrapper">
```

Здесь же подключается или выводится шапка сайта. Заголовок вкладки формируется поддержкой `title-tag`; ресурсы регистрируются через enqueue. SEO-теги выводит выбранный источник без дублирования.

`footer.php` выводит подвал, закрывает каркас и вызывает хук:

```php
</div>
<?php wp_footer(); ?>
</body>
</html>
```

Шаблон страницы содержит сборку секций:

```php
<?php get_header(); ?>
<main class="page">
  <?php
  while ( have_posts() ) :
      the_post();
      get_template_part( 'Parts/common/content', null, array( 'content_id' => get_the_ID() ) );
  endwhile;
  ?>
</main>
<?php get_footer(); ?>
```

`Parts/common/content.php` реализует фактический вывод. Части страницы не содержат повторных `html`, `head` и `body`. Проверяем наличие всех подключаемых файлов: отсутствующая часть не должна молча оставлять незамеченную дыру на странице.

## Создание страницы

1. Создаём страницу в WordPress, назначаем родителя и адрес по заданию.
2. Используем подходящий шаблон иерархии либо отдельный выбираемый шаблон с `Template Name`. Не создаём уникальный PHP-файл для каждой записи, если достаточно одного шаблона.
3. Привязываем к шаблону или странице группы ACF; внутри используем вкладки блоков с размещением слева.
4. Общие секции подключаем через `get_template_part()`, передавая данные, а не копируя HTML и тексты между страницами.
5. Добавляем страницу в нужные меню через админку. Внутренние адреса получаем средствами WordPress.

## Контент и формы

- Содержимое редактора выводим через предусмотренный механизм WordPress, поля ACF — после проверки плагина, типа значения и контекста.
- Не закрепляем произвольные ID страниц, меню и форм в PHP. Настройки и связи должны сохраняться при переносе.
- Общие настройки хранятся в Customizer. Отзывы, услуги и другие повторяющиеся записи выбираются из соответствующих разделов.
- Contact Form 7 выводится по выбранной в настройках форме. Дополнительный контейнер секции или попапа не создаёт внешний `form` вокруг формы плагина.
- Предусматриваем пустые необязательные поля, изображение записи, 404 и нужные архивы. Хлебные крошки выводим по структуре сайта, если они предусмотрены дизайном.

Официальные справочники: [иерархия шаблонов](https://developer.wordpress.org/themes/basics/template-hierarchy/), [части шаблонов](https://developer.wordpress.org/reference/functions/get_template_part/), [хуки каркаса](https://developer.wordpress.org/reference/functions/wp_body_open/).
