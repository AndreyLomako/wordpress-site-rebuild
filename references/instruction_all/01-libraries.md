# Библиотеки в теме WordPress

## Выбор и хранение

- Для новых слайдеров используем Swiper; для галерей, лайтбоксов и попапов — Fancybox, если задание не определяет другой вариант.
- Библиотеки храним локально в `assets/lib/<library>/`. Подключаем только нужные ресурсы; не включаем библиотеки на страницах, где они не используются, если это можно надёжно определить.
- Версию выбираем по совместимости с проектом и проверяем по официальной документации. Предпочитаем минифицированные файлы; если сборка их не содержит, используем предоставленные. Лицензионные файлы и необходимые файлы дистрибутива сохраняем.
- Карты, платёжные сервисы и другие внешние API могут требовать удалённые ресурсы. Их не объявляем локальными библиотеками и не подменяем неработающими копиями.
- При полном переносе можно заменить исходную библиотеку, если сохраняются оформление, доступность и все нужные сценарии. Не обновляем все зависимости и не переписываем сторонние виджеты при узкой правке.

## Подключение

Подключаем CSS и JS через `wp_enqueue_style()` и `wp_enqueue_script()` на хуке `wp_enqueue_scripts`, задавая URI темы, версии и зависимости. Порядок: CSS библиотек → основные стили → адаптив; JS библиотек → код темы. Не добавляем вторые ручные теги подключения в `header.php` и `footer.php`.

- Локальным файлам задаём версию по времени изменения с проверкой существования. Не используем текущее время на каждом запросе.
- Сохраняем штатные подключения Contact Form 7 и других нужных плагинов. Не отключаем их стили и JS до проверки зависимостей.
- JS, работающий после построения DOM, подключаем в подвале или с подходящей поддерживаемой стратегией загрузки. При выборе стратегии проверяем порядок исполнения зависимостей.

## Swiper

- Сохраняем структуру `.swiper` → `.swiper-wrapper` → `.swiper-slide`, дополняя её собственными БЭМ-классами.
- Инициализируем каждый экземпляр относительно его корневого элемента. Кнопки и пагинацию ищем внутри соответствующего блока; общий селектор не должен связывать разные слайдеры.
- Стили пишем на своих классах. Системные классы состояний библиотеки используем по назначению; не ломаем скрытие навигации через `.swiper-button-lock`.
- Скорость, loop, autoplay, число видимых слайдов, отступы и брейкпоинты определяются дизайном или наблюдаемым поведением оригинала. Единую произвольную скорость всем слайдерам не навязываем.
- Для вкладок, которые действительно работают как синхронизированные слайдеры, подходит Swiper Thumbs. Обычным вкладкам не добавляем библиотеку без необходимости.

## Fancybox и формы

- Для галереи задаём отдельную группу, для попапа — уникальный ID контейнера. API инициализации сверяем с установленной версией.
- В контейнер попапа выводим Contact Form 7 без внешнего вложенного тега `form`.
- Проверяем открытие, закрытие, Escape, возврат фокуса, прокрутку страницы и открытие триггера внутри слайдера.
- При нескольких экземплярах одного блока не допускаем дублирования DOM ID и обработчиков событий.

Справочники: [подключение ресурсов WordPress](https://developer.wordpress.org/themes/core-concepts/including-assets/), [Swiper](https://swiperjs.com/swiper-api), [Fancybox](https://fancyapps.com/fancybox/).
