# HTML-разметка внутри PHP-шаблонов

## БЭМ

Используем `.block`, `.block__element` и отдельный класс модификатора `._is-active`. Составной селектор — `.block._is-active`. Слова разделяем дефисами; классы библиотек и плагинов сохраняем, дополняя своими.

```html
<section class="about">
  <div class="container">
    <div class="about__wrapper"></div>
  </div>
</section>
```

Не добавляем пустые секции: пример показывает только структуру обёрток. ID используем для якорей, связей полей и элементов управления, а не для CSS-стилизации. Отступы HTML — 2 пробела; в PHP придерживаемся принятого в проекте форматирования.

## Содержание и семантика

- Разметка отражает смысл: `header`, `footer`, `main`, `nav`, секции, списки и последовательная иерархия заголовков. Не запрещаем семантические теги только ради стилевого соглашения.
- Для действия используем кнопку с подходящим `type`, для перехода — ссылку. Меню и логотип ведут на реальные адреса WordPress; логотип обычно ведёт на главную через `home_url()`.
- Меню получаем через WordPress, сохраняя вложенность и текущий пункт. Не дублируем список ссылок вручную в каждом шаблоне.
- Телефоны и email кликабельны через `tel:` и `mailto:`. Не требуем для них открытия новой вкладки. Для внешних ссылок поведение и `nofollow` определяем по назначению; при новой вкладке предусматриваем `noopener`.
- Картинкам задаём корректный `alt`, элементам формы — подписи. У интерактивных контролов должны быть понятные имена и доступный фокус.

## Динамические значения

- Обычный текст выводим через экранирование текста, атрибуты — через экранирование атрибутов, URL — через экранирование URL.
- HTML-контент выводим через предназначенный для этого механизм WordPress или фильтрацию разрешённых тегов. Не экранируем целиком уже подготовленный вывод меню, изображения или формы так, чтобы HTML превратился в текст.
- Данные проверяем до вывода. Не создаём пустые ссылки, заголовки и изображения для незаполненных необязательных полей.
- Основные стили храним в CSS. Динамические размеры и параметры библиотек допустимы там, где они необходимы; SVG-атрибуты не считаются inline-стилями.

При переносе изменение структуры HTML и классов допускается только с сохранением визуального результата и работы сценариев.
