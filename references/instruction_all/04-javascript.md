# JavaScript темы

- Собственный код пишем на Vanilla JS. Основной файл — `assets/js/main.js`; подключение выполняется через WordPress после зависимостей. Сборщик и Babel не обязательны.
- Порядок секций: утилиты → компоненты → слайдеры → поведение страниц. Каждый компонент изолируем в IIFE или функции инициализации.
- Проверяем существование элементов и нужной библиотеки. Отсутствие компонента на странице не должно останавливать весь файл.
- При нескольких одинаковых блоках инициализируем каждый относительно его корня. Не используем один глобальный селектор для кнопок всех экземпляров.

```javascript
(function () {
  document.querySelectorAll('.accordion').forEach(function (root) {
    const button = root.querySelector('.accordion__toggle');
    const panel = root.querySelector('.accordion__panel');
    if (!button || !panel) return;
    button.addEventListener('click', function () {
      const expanded = button.getAttribute('aria-expanded') === 'true';
      button.setAttribute('aria-expanded', String(!expanded));
      panel.hidden = expanded;
      root.classList.toggle('_is-active', !expanded);
    });
  });
})();
```

Пример показывает привязку обработчиков и состояние. Для требуемой анимации добавляем отдельную реализацию перехода без потери доступности скрытого содержимого.

## Данные и события

- JS переключает классы и состояния; анимацию собственных компонентов описываем в CSS. Не назначаем `style.display` для обычного открытия и закрытия компонентов.
- URL, параметры карты и настройки берём из WordPress: через экранированные data-атрибуты или JSON, сформированный `wp_json_encode()` и переданный с нужным скриптом. Не записываем домен и контакты прямо в JS.
- Не вставляем PHP-код в статический `.js`-файл. При передаче динамической конфигурации учитываем порядок загрузки и контекст экранирования.
- Плагиновые формы работают через события и API Contact Form 7. Не дублируем их отправку собственным обработчиком и не считаем клик по кнопке успешной отправкой.
- При повторном показе блока или обновлении его содержимого избегаем повторного назначения обработчиков и создания второго экземпляра слайдера.
- Изменение размеров экрана и возврат по истории браузера не должны ломать состояние меню, вкладок и фильтров. Сценарии проверяем на реальной странице WordPress.
