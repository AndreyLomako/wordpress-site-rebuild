# Наполнение сайта через админку

## Где редактируются данные

| Данные | Место редактирования | Результат |
| --- | --- | --- |
| Логотип, название, иконка сайта | Свойства сайта в настройках WordPress | Единое оформление шапки, подвала и вкладки браузера |
| Телефоны, email, адреса, график, мессенджеры и социальные сети | «Внешний вид → Настроить → Контактная информация» | Общие значения обновляются во всех использующих их блоках |
| Параметры карты | «Внешний вид → Настроить → Карта» | Меняются положение, масштаб, подпись и метка |
| Общие тексты подвала и другие сквозные настройки | Соответствующие разделы Customizer | Общие данные не дублируются в полях каждой страницы |
| Аналитика и разрешённый сторонний код | Раздел счётчиков и интеграций в Customizer | Подключение в предусмотренных местах и возможность отключения |
| Состав и порядок меню | Стандартное управление меню WordPress, включая Customizer | Отдельные области шапки, мобильной навигации и подвала |
| Заголовки, тексты, изображения и настройки секций страницы | ACF в редакторе конкретной страницы | Свои данные каждой страницы |
| Превью записи | Поле изображения записи в редакторе | Изображение карточки или страницы записи |
| Отзывы, преимущества, услуги и другие самостоятельные сущности | Нужные проекту разделы админки | Одно место редактирования и повторное использование |

Создавай только разделы и поля, нужные конкретному проекту. Если у сайта несколько адресов или телефонов, предусмотри подходящую структуру данных; не ограничивай такой сайт одним контактом. Общее значение и его переопределение для страницы должны быть явно различимы.

Пример расположения разделов настроек: [Customizer](images/customizer.png). Скриншот показывает организацию интерфейса; набор разделов определяется проектом.

## Общие настройки

- Добавь понятные русские названия, подписи и подсказки. Выбирай подходящий элемент управления: текст, многострочное поле, URL, число, изображение или выбор из существующих данных.
- Сохраняй общие значения в настройках WordPress и получай их единым способом во всех шаблонах. Не подставляй реальные контакты или адреса проекта в PHP как резервные значения.
- Ссылку для звонка формируй автоматически из номера; видимое написание номера сохраняй. Для email используй почтовую ссылку.
- Для карты предусматривай нужные выбранному сервису параметры. Если используется управляемая карта, редактируются координаты центра и метки, масштаб, подпись и изображение метки. При использовании готового встраивания настройка должна соответствовать его возможностям.
- Для аналитики отдельно предусматривай включение на рабочем сайте и отключение на стенде. Запрет индексации сам по себе не является признаком тестового окружения.
- Произвольные скрипты, включая код в `head` и перед закрытием `body`, допускаются только для пользователей с соответствующими правами. При сохранении текстов и HTML-контента используй подходящую очистку данных.

## Страницы и ACF

- Создай группы полей, привязанные к нужным страницам или шаблонам. Слева показываются вкладки блоков, справа — поля выбранного блока: [пример формы редактирования](images/acf-page-tabs.png).
- Для полей используй названия по смыслу: заголовок, текст, изображение, подпись кнопки, ссылка, якорь, оформление, видимость. Добавляй только параметры, влияющие на конкретный блок.
- Для одного смыслового блока сохраняй предсказуемую структуру полей. Имена и ключи должны совпадать с тем, как тема получает данные.
- В полях выбора меню показывай существующие меню WordPress. Если своё меню страницы не выбрано, используй общее. Сохраняй вложенность там, где она нужна навигации.
- Изображения выбираются из медиатеки; формат значения ACF согласуется с выводом темы. Существующие записи выбираются связями, а не копированием их текстов.
- Для обычных текстов сохраняй введённые переносы строк. Поля с форматированием отделяй от обычных текстовых полей.
- Если поля или изображение не заполнены, не выводи пустые кнопки, сломанные изображения и бессодержательные контейнеры. Обязательные для блока данные явно обозначь в редакторе.
- Если страница полностью собирается через ACF, классический редактор или отключение блочного редактора допустимы для этого типа контента. Не отключай редактор и ресурсы ядра глобально без проверки потребностей остальных страниц и плагинов.

## Повторяющиеся сущности

- Для самостоятельных сущностей создай отдельные типы записей с понятными названиями, иконками и действиями в админке: [пример размещения разделов](images/admin-sections.png).
- Запись, используемая только как часть секции, доступна для редактирования, но не получает отдельную публичную страницу. Если сущности нужна своя страница, предусмотри её адрес и шаблон.
- Дай возможность задавать порядок вывода. Учитывай его в запросах сайта и, где это помогает редактированию, в списках админки.
- Условия выбора записей и их связи со страницами храни явно. Изменение повторно используемой записи должно обновлять все места её вывода.

## Формы

- Формы создаются и редактируются в Contact Form 7. В настройках блока сохраняется ссылка на нужную форму или её идентификатор; не дублируй её разметку в PHP.
- Сохраняй согласованные подписи, поля и оформление. Предусмотри состояния отправки, ошибок и успешного результата, а также требуемое заданием согласие пользователя.
- Не показывай успешный результат до подтверждения обработки формы. Обработку и отправку не заменяй визуальной имитацией.

## Критерий готовности наполнения

Заказчик может заменить общие контакты и логотип, настроить меню, заполнить страницу и изменить повторяющиеся записи через админку без правки PHP, CSS и JavaScript. После переноса доступны определения полей и все данные, необходимые для такого редактирования.
