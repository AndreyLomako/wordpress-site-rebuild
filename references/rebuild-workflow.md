# Обследование источника и сравнительная проверка

## 1. Карта страниц

Собери обнаруживаемые URL из главной навигации, подвала, внутренних ссылок, пагинации и доступных sitemap. Не считай несколько страниц с общей шапкой одной страницей. Раздели экземпляры контента и повторяемые типы шаблонов: страница услуги, статья, архив и другие фактически найденные типы.

Для полного переноса веди компактный реестр: исходный URL, тип шаблона, целевой URL, статус получения ресурсов, статус реализации и проверки. Отмечай дубли, редиректы и недоступные адреса. Если раздел содержит неопределённо большое или закрытое содержимое, уточни границы, продолжая известную часть работы.

## 2. Наблюдение через браузер

- Для каждого типа страницы изучи весь экран по вертикали: шапку, секции, фиксированные элементы, формы, подвал и плавающие кнопки.
- Сохрани скриншоты на выбранных ширинах; записывай фактические размеры окна, масштаб и состояние. Дождись загрузки шрифтов и нужного содержимого.
- Проверь промежуточные ширины и смену компоновки. Установи реальные брейкпоинты по доступному CSS и наблюдению.
- Открой меню, попапы, вкладки и аккордеоны; проверь слайдеры, галереи, фильтры, поиск, ссылки и состояние cookie-плашки. Зафиксируй события, переходы и результат.
- Отдельно запиши состояния форм: исходное, валидация, отправка, результат. Не отправляй тестовые заявки в рабочие каналы без соответствующей авторизации; проверку доставки выполняй на целевом тестовом окружении.
- Используй возможности доступного браузерного инструмента для чтения DOM, CSS и ресурсов только в рамках разрешённого им API. Если функция недоступна, выбери доступный способ или обозначь ограничение.

## 3. Фиксация ресурсов

Сохраняй ресурсы в рабочую папку и веди соответствие исходного URL и локального файла. До переименования проверь цепочку: HTML → CSS/JS → вложенные CSS, шрифты, фоны, иконки и дополнительные файлы библиотеки. Для CSS относительные адреса разрешаются относительно исходного CSS-файла, а не адреса страницы.

- Учитывай query-параметры версий, разные файлы с одинаковым именем и шрифтовые подмножества. Не перезаписывай разные ресурсы одним файлом.
- Для изображений проверяй `src`, `srcset`, lazy-loading, CSS-фоны, мобильные версии и кадрирование. Скачанный thumbnail не всегда заменяет исходное фото.
- Сохраняй наблюдаемые значения шрифтов, контейнеров, размеров и состояний. Не считай список подключённых файлов доказательством того, что всё содержимое получено.
- Сторонние домены разделяй по назначению: ресурсы дизайна, интеграции и аналитика. Аналитика и доставка заявок настраиваются для целевого сайта.
- Не пытайся восстановить скрытый серверный код из внешнего вида. Нужные функции реализуй средствами WordPress по наблюдаемому поведению и заданию; неизвестные расчёты не выдумывай.

## 4. Перенос данных и связей

До массового наполнения свяжи типы страниц со своими PHP-шаблонами и ACF-группами. Сначала реализуй и сверь один экземпляр каждого типа, затем заполняй остальные и проверяй их отличия.

Общие контакты и сквозные блоки редактируются один раз. Контентные изображения импортируются в медиатеку; ID полей, файлов и форм берутся из целевого WordPress. Ссылки на исходный домен, которые должны вести внутрь нового сайта, заменяются адресами WordPress. Для внешних ссылок, карт и сервисов сохраняется правильное назначение.

## 5. Сверка

Сравни оригинал и целевую страницу при одинаковых ширине, высоте, масштабе, позиции прокрутки и состоянии. Для анимаций и динамического содержимого выбери сравнимый момент; не принимай разницу состояния за ошибку стилей.

- Сначала сравни контейнер, шрифты, основные размеры и сетку; затем детали карточек, кнопок, иконок и отступов.
- Проверь первый экран и всю высоту страницы, мобильное меню, попапы и длинные тексты.
- Проверь переходы, обработчики, ввод в формы и состояние элементов после смены ширины.
- Проверь отсутствие пропавших ресурсов и ошибок консоли. Отдельно проверь смену настроек и контента через админку.
- В реестре отмечай результат для каждой страницы, а также неустранённые отличия и недоступные зависимости.

Передача не включает автоматическую публикацию нового сайта или замену рабочего домена: это отдельное действие по поручению пользователя. Итоговое сообщение должно различать реализованное, проверенное и то, что требует доступа или настройки.
